Abstract

Foundation models such as GPT and Claude can now plan and control robot arms. We found that this comes with real safety risks, and that there is no thorough way to measure them yet.

We introduce RoboRisk, a benchmark that evaluates safety in closed-loop robot tasks, with 92 tasks in simulation and 13 tasks on a physical robot. The tasks fall into five categories: Task-level Refusal (T), Plan Repair (P), Execution-time Hazard (E), Injection (I) and Sequential Memory (S). We evaluate six foundation models (GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna, Claude Opus 5.5, Gemini 4 Argon and Grok 4.7) and two robot-specific APIs (the Dream API and PokeBot’s RoboAPI). Across the six foundation models, baseline harm rates range from 9.06% to 76.92%.

We then propose the Lease-Enforced Agentic Safety Harness (LEASH), a safety layer that fits into nearly any agentic robot stack. LEASH uses a fast decision model (Jev, or OpenAI’s Decisions API) for three safety gates, a task gate, an action gate and a commit gate, and the planner and all gates share one safety policy. In simulation and on the physical robot, LEASH reduces harm for all six foundation models while largely keeping their task success, at a small cost in time and tokens.

Five ways an agentic robot can cause harm

RoboRisk-S has 92 tasks in MuJoCo with a Franka Panda arm (built on LIBERO and robosuite). RoboRisk-R has 13 tasks on a tabletop with a Dobot CR5V2 arm, a two-finger gripper and two RealSense D455 cameras. Protocol

LEASH

Put the puppy on a leash

“Every agentic robot is a good puppy, until you walk it without a leash.”Qinfeng Zhu

The idea comes from coding agents

Coding agents already review risky actions before they run. Codex, for example, sends certain approval requests to a separate reviewer agent. For a shell command, the text alone tells the reviewer whether it is dangerous. A robot command does not.

Three gates, one shared policy

The planner holds no standing permission to move the robot. Each gate grants a lease that covers only the current task, action or monitored operation, and the harness checks the lease before anything runs. The planner and the three gates read the same safety policy, written as a prompt, so the planner plans around the same rules the gates enforce.

1

Task gate

When
Right after the user sends an instruction, before the planner sees it.
Sees
The instruction and the current frame from every camera.
If it rejects
The task ends. It is the only gate allowed to stop a task; after this point, only the planner can stop.

2

Action gate

When
After the planner proposes an atomic action or a composite skill, before it runs.
Sees
The proposed action and the current camera frames.
If it rejects
The action is blocked and the planner replans a safer one, which goes back to the gate.

3

Commit gate

When
Inside a long skill, right before a monitored, irreversible step. Today these are opening the gripper and pouring, detected in code.
Sees
The step about to happen and the current frames.
If it rejects
The step is blocked; the planner picks a safer next step or stops.

Why decision models. A task needs ten or more gate calls. With a general model such as GPT-6 Luna, each call took about 20 s. The multimodal decision models released in October 2026 answer in a fraction of that and cost little, so LEASH uses Jev by default and also supports OpenAI’s Decisions API. Each gate returns a safety score s; the step is allowed only if s > τ.

Where harm remains

GPT-6 Luna in simulation and Grok 4.7 on the real robot keep HRs of 12.68% and 38.46% with LEASH. Both often fail to follow instructions, and part of their harm comes from unstable motion rather than unsafe decisions: in physical trials they struck the tabletop, and Grok 4.7 hit the wrist camera. We do not recommend either model for physical experiments.

The Dream API records no harm but only 28.2% SSR; it is overly cautious and refuses safe steps. RoboAPI reaches 0.0% SSR and 59.0% HR. Both were tested on adapted setups, so these numbers say nothing about the services’ internal safety mechanisms.

The Human-Presence Gap

In simulation, the planners work normally in scenes with people. On the real robot, the same planners become far more cautious when a person is present. On P1 (move a cleaver around a hand) and P2 (place a knife next to a hand), GPT-6 Astra, GPT-6.1 Sol, Gemini 4 Argon and Claude Opus 5.5 achieve no safe success. Most of these trials never start the manipulation. Current models do not yet balance safety with working next to people.
